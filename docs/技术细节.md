# 技术细节：1 血为什么这样改

---

## 1. 为什么 1 血必须动 `RepairStep`

游戏算维修费的函数（`game.exe` 0x6DAEC0，建筑/单位/步兵/飞机四张虚表共用）：

```
X = 对象造价
A = 血量上限（Strength）
q = A / Rules[RepairStep]          ← 整数除法，会截断
维修费 = max(1, (X / q) × RepairPercent)   ← q=0 时这里除零
```

| 血量 | `RepairStep` | 商 q | 结果 |
|---|---|---|---|
| 125 ~ 1500（原版） | 8 | ≥ 15 | 安全 |
| 5（5 血版） | 8 | **0** | ✗ `EXCEPTION_INT_DIVIDE_BY_ZERO` |
| **1（本模式）** | 8 | **0** | ✗ 崩 |
| **1（本模式）** | **1** | **1** | ✓ 安全 |

所以规则文件里 `RepairStep=1`、`IRepairStep=1` 是**硬要求**，不是可调项。
顺带一提：即使血量是 2 或 3，`2/8`、`3/8` 也都是 0 —— 只要血量 < RepairStep 就必崩。

### 语义还成立吗
`q = 血量/RepairStep` 本质是"修满要几个 tick"。1 血 + `RepairStep=1` → q=1 → 一次修满，
总费用 = 造价 × `RepairPercent`(15%)，和原版"修满一共 15% 造价"完全一致 ✓

## 2. 为什么这次不需要 exe 补丁

5 血版的修复是**两层**：`RepairStep=1`（让 5/1=5）+ exe 补丁（把商固定成 5，物理上封死）。
本模式 `1/1 = 1 ≥ 1`，第一层就够了，所以：

- **不用打补丁**
- 而且**必须确保 exe 是原版**：5 血那个 `mov eax,5` 会把商固定成 5，
  1 血时等于"以为要修 5 次"，每次收 造价/5 × 15% → 修一次收 3%，而实际一次就满血 → 被多收好几倍

一键脚本 `--check` / 安装时都会读 `0x2DAEDC` 处 6 字节判断：
`F7 B9 34 13 00 00` = 原版；`B8 05 00 00 00 90` = 5 血补丁（会被自动还原）。

## 3. 0 血类型：1 血的隐形炸弹

有些类型"在类型表里有、但段落缺失或被注释"，引擎给它们 `Strength=0`。`0/1 = 0` → 除零。
本仓库在两份规则文件里都补成了 `Strength=1`：

| 版本 | 情况 | 类型 |
|---|---|---|
| 原版 | 有段落缺键 | `[DeathDummy]` |
| 原版 | 段落完全缺失 | `APACHE` `NAWAST` `GARADR` `NAHPAD` `CAEURO01` `CAIRSFGL` |
| 尤里 | 有段落缺键 | 2 个（引擎占位类型） |
| 尤里 | 段落完全缺失 | `YDUM` `APACHE` `CASYDN01` `CATIME` `CALA02` `CALOND02` |

## 4. 任务包只能"等长"改，而这次正好最省事

任务包（`.mix` / `.mmx` / `.yro`）的索引用 Blowfish 加密
（头 `flag=0x00010000` 表示加密头、`0x00020000` 表示带校验），索引里记着每个内部文件的偏移与长度。
**改长度就得重写加密索引**，风险极高。

本模式的目标值是 **1 位数**，所以"变短"永远安全：

```
Strength=1000\r\n   →   Strength=1   \r\n      （3 个空格补齐，长度不变）
Strength=800\r\n    →   Strength=1  \r\n
Strength=10000\r\n  →   Strength=1    \r\n
```

对比 1500 版（`tanky-ra2-ai`）的麻烦：目标值 4 位数，遇到 `Strength=250` 这种 3 位数还得
在**同一段落内删掉等量字节**（空行/注释行/重复的语音列表项）来"借字节"。1 血完全没这问题。

### 改完必须做的结构自查

跟原版备份逐项对比，必须全对：

- 文件大小
- 段头总数（`^\[...\]`）
- `[Basic]` `[Header]` `[Map]` `[MultiMaps]` `[Digest]` `[IsoMapPack5]` `[Structures]`
  `[Units]` `[Infantry]` `[Triggers]` `[Waypoints]` `[TeamTypes]` 的出现次数
- 不能出现 `asic]` / `eader]` / `ultiMaps]` / `igest]` 这种"少了左括号"的残片

## 5. 为什么留 `SAPC` 和 `CANEWY04`

1 血是所有东西都一碰就死，但**任务脚本有硬依赖**：

| 类型 | 任务 | 原值 | 压到 1 会怎样 |
|---|---|---|---|
| `[SAPC]` 气垫船 | 苏军第二关 | 800 | 运兵船一碰就沉，任务没法打 |
| `[CANEWY04]` 自由女神像 | 盟军第一关（守）/ 苏军第三关（地标） | 10000 | 一开局就被打没，直接失败 |

这两个是"任务原本就特意加强的值"，不是漏改。其余全部压成 1。

---

## 6. 降负载（1 血比 5 血更需要）

1 血时每一发子弹都可能触发爆炸，碎片、烟尘、殉爆的**数量级**比 5 血高得多。
苏军第三关结尾"大批单位被控制"那里曾崩过一次 `EXCEPTION_ACCESS_VIOLATION`（`0x787B2A`，
链表+位图写野指针，`Ecx=0x1100` 这种"小整数被当指针"），属于"内存先被写坏、后面才炸"的类型。

所以压掉纯视觉的负载：

| 键 | 处理 | 代价 |
|---|---|---|
| `MaxDebris` | ≤ 4 | 碎片动画变少 |
| `MinDebris` | ≤ 1 | 同上 |
| `DamageParticleSystems` | 每类 1 套（建筑 `BigGreySmokeSys` / 单位 `SmallGreySSys`） | 烟尘变少 |
| `[OilExplosionWH] DelayKillFrames` | 15 | 连环爆分帧更明显 |

**连锁伤害一点没改**：`DeathWeapon=`、`CausesDelayKill=yes`、`CellSpread=` 全部原样 —— 那是这个玩法的灵魂。

## 7. 尤里的复仇：规则不在散装文件里

- 原版有散装 `rules.ini`；尤里没有，`rulesmd.ini` 打包在 `expandmd01.mix` / `ra2md.mix` 里，索引加密
- 但 `rulesmd.ini` 抬头写着：*If placed in game directory, it will override built in values.*
- 所以：**往游戏目录放一份散装 `rulesmd.ini` 就盖住打包里那份**，打包文件一个字节都不用动

### 基线怎么抠的
包里那份规则是**不压缩的明文**：

1. 在 `expandmd01.mix` 原始字节里搜 `; RULE*.INI` → 起点
2. 用另一份已知内容的 `rulesmd.ini`（`expand01.mix` 里那份）**末尾 160 字节**当锚点 → 终点
3. 截出 743,215 字节的完整 YR 规则

### 为什么用 `expandmd01.mix` 那份
这整合版里有 **3 份** `rulesmd.ini`：

| 包 | 大小 | 说明 |
|---|---|---|
| `expandmd01.mix` | 743,215 | YR 扩展包，**加载顺序最优先** |
| `ra2md.mix` | ≈742,958 | 核心包（不同版本） |
| `expand01.mix` | 745,825 | 被改过（`[SPY] Prerequisite=none`、`;zhuijianspy`），不是基线 |

YR（`gamemd.exe`）的 MIX 加载顺序是 `expandmd##` → `ra2md` → `expand##` → `ra2`，**先命中先用**，
所以实际生效的是 `expandmd01.mix` 那份。三份的开头 133,832 字节完全相同、之后各走各的 —— 确实是三个版本。

---

## 8. 存档的坑（最容易误判）

红警的 `.sav` 里存的是**当时那份场景**（解析后的对象、触发、各类型血量）。所以：

- 应用新规则后，**读旧存档仍然用旧血量** → 看起来像"改了没用"
- 正确做法：**新开**关卡/遭遇战；战役从"新战役"进
- 想验证：把对应的 `*.sav` 改名藏起来，逼游戏重新生成场景

## 9. 想自己调，改哪里

| 想干什么 | 改哪里 |
|---|---|
| 血量数值（比如改成 2 血） | 两份规则里所有 `Strength`；但**`RepairStep` 必须 ≤ 最小血量**，2 血就得 `RepairStep=2`（或 1） |
| 某个必须守的目标又被秒了 | 往 `apply_onehp_mod.py` 的 `MODES[...]['keep']` 里加段落名，重跑 |
| 画面更流畅 | 继续压 `MaxDebris` / 把 `DamageParticleSystems` 整段注释掉 |
| 连锁更疯 | `[OilExplosionWH] CellSpread`、各死亡武器的 `CellSpread`（注意别把帧数调太低，会卡） |

改规则文件是安全的（松散文件，长度随便变）。改任务包**永远只能等长**，没有例外。
